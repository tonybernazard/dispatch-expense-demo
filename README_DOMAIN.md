# Expense policy API

Pure ES module: `src/domain.js`. No network, storage, timestamps, or mutation. Job IDs may be any nonblank string; optional `policy.allowedJobs` restricts them to an explicit array of IDs.

- `initialPolicy`: fictional employer policy; receipt threshold $10, meal cap $75 per day, flight cap $650 per claim, per diem $80 per date, effective-dated mileage rates, editable category GL codes.
- `categories`: category label strings. `jobs`: `{id, code, name}` objects; expense `job` contains the ID. `seedExpenses`: eight fictional expenses. `cardTransactions`: five fictional transactions with `{id, date, merchant, amount, cardLast4}`.
- `amountOf(expense, policy)`: cent-rounded gross amount. Mileage derives from `miles × mileageRate(date)`; per diem derives from `perDiemRate × dayFraction`. Both ignore the entered amount until approval. Approved/exported rows use `approvedAmount` when supplied, preserving gross amounts across later rate changes.
- `mileageRate(date, policy)`: latest effective rate on or before an ISO date, or `null`. Employer-selected 2026 benchmark: $0.725 from January 1, $0.76 from July 1. Source: https://www.irs.gov/tax-professionals/standard-mileage-rates and https://www.irs.gov/irb/2026-29_IRB (Announcement 2026-11). These defaults are configurable and are not tax advice.
- `evaluateExpense(expense, policy, allExpenses = [])`: `{errors, warnings, cap, reimbursable, employeeOwes, amount}`. Pass all records to detect same-day allowance/meal conflicts and duplicate card matches. `cap` is a number or `null`; messages are strings.
- `totals(expenses, policy)`: `{reimbursable, employeeOwes, corporate, total}` for the supplied scope, excluding soft-deleted rows. Total is gross reported spend. Corporate is card spend less approved recovery decisions. Rejected employee-paid claims have no reimbursement. Corporate rejection does not reverse a card charge or create debt. Estimates can include drafts; filter to approved rows for payable totals.
- `transition(expense, action, note = '', decision = {})`: returns a copy with status and appended history, or throws. Draft/returned → submit → submitted; submitted → approve/return/reject; approved → export. Return/reject require a reviewer note. Rejected/exported are terminal. Corporate personal spend requires an explicit `decision.recoveryAmount` (zero is allowed), or an existing `expense.recoveryAmount`, at approval. It must not exceed `deductiblePersonal`; the approved decision is copied to the record and history. Supply `decision.amount` and `decision.reimbursable` from the current validated assessment to save `approvedAmount` and `approvedReimbursable`; approved/exported assessments preserve this reimbursement snapshot even when policy or other claims change. Legacy three-argument approvals remain supported but do not create a reimbursement snapshot. Validate before submit or approve; transition guards workflow and the recovery decision.
- `makeExport(expenses, policy)`: CSV string with approved rows only, category GL mapping and separate reimbursement, personal debt, and company-card amounts. Throws for invalid approved rows and missing/blank category GL mappings. An explicit `policy.glCodes` is the complete mapping, rather than a partial overlay; missing mappings do not block draft/submission evaluation. Does not mark records exported; call `transition(row, 'export')` only after successful file creation. CSV text fields are formula-neutralized and escaped.

## Policy boundaries

- Ordinary receipt evidence is optional only below $10. At $10 or more, a receipt or both `missingReceipt: true` and nonblank `missingReason` is required. Mileage instead requires `mapAttachment`; per diem requires no receipt.
- The meal cap is shared across all active same-date meal claims. Approved/exported claims consume the allowance first, then other stages; stable IDs order claims within each stage. The result `cap` is the current claim’s remaining allowance. Rejected/deleted claims are excluded. Above-cap spend requires an `exceptionNote`; this explains the exception but does not raise reimbursement. Pending amounts are live estimates. Approved/exported employee-paid claims consume their saved reimbursement snapshot; supplied approval snapshots stay fixed even if sorting or later approvals change. Without a snapshot, legacy records still use live estimates.
- Employee-paid reimbursement is business spend, capped where applicable. `deductiblePersonal` is excluded. Corporate cards never create reimbursement. Personal spend alone does not create debt: only an explicit `recoveryAmount` on an approved/exported expense creates employee-owed money, bounded by `deductiblePersonal`. Rejected claims always have zero employee debt. Over-cap amounts never create automatic debt.
- Per diem requires nonblank `tripPurpose` and `location`, explicit `eligible: true`, and `dayFraction` equal to 0.5 or 1. Per diem conflicts with actual Meals on the same date, and duplicate per diem dates are blocked. Rejected or deleted claims do not block a meal/per-diem date. This demo represents one employee.
- Mileage plus Fuel for the same job/date requires an exception note explaining the overlap. Rejected/deleted records are excluded from this check.
- A `cardId` may be matched only once among nondeleted expenses, including rejected claims. A rejected report does not make its underlying transaction available for duplicate matching.
- Dates are validated as real `YYYY-MM-DD` dates. Missing historical mileage rates are an error; future rates are never back-applied.

Run unit tests: `node --test src/domain.test.js`.
